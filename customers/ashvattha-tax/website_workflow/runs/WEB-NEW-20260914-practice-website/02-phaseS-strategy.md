MATRIX WINNER: **D** (WhatsApp) at 405 — and **D cannot be built**: the number was not
supplied. Option B, the form, cannot complete either: its backend is default-deny and
unapproved. The matrix has no feasibility gate, so an option blocked on missing customer
input outscored the options that can ship. That is recorded as a framework gap, not
resolved by quietly re-weighting.

DECISION RECORDED: **D is the target, BLOCKED on customer input (the WhatsApp number).**
Until it arrives, the only buildable route is **C**, an email link to the owner-supplied
`hello@ashvattha-tax.example` (360). C is a fallback chosen by feasibility, not a matrix win.
FALSIFIER: the WhatsApp number arrives (D ships), or the owner approves an email service
for the form (B becomes completable).
Note: the form is still generated from its contract, rendered disabled and marked
unconfigured, because the owner requested it; it must not appear to submit.
