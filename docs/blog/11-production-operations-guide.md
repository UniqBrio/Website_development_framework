# 11 — Production operations guide

The routine for publishing an already-written blog to a production website,
as an operator. Supporting detail: 05 (preview and approval), 06 (publishing),
15 (concurrency), 16 (incidents), 07 (security).

## Preconditions (once per machine)

- Node ≥ 18, Python ≥ 3.8 as `python`; `npm ci` in the framework.
- Optional tools for the formats you expect: poppler, LibreOffice, ffmpeg,
  tesseract. `python website_workflow/tools/blog_ingest.py --capabilities`.
- For untrusted packages: run the ingest inside a container or VM (07,
  "Sandboxing"). The ingest's own limits are a floor, not a sandbox.

## Preconditions (every publish)

1. The site repository is clean (`git status` empty) or its changes are
   understood. This is the backup of record.
2. `npm run blog -- inspect-site <site>` says SUPPORTED, and you have read its
   review items (for example "the root layout renders no header" or "the
   sitemap is generated by code").
3. No other publish is running (`npm run blog -- lock-status <site>`).

## The routine

| Step | Command | Who | Output to keep |
|---|---|---|---|
| 1 Ingest | `npm run blog:ingest -- <package> --out website_workflow/blog_runs/<id>` | operator | ingest summary |
| 2 Preview | `npm run blog -- preview <run> --site <site> --origin https://…` | operator | `<run>/preview/`, `<run>/reports/` |
| 3 Compare (recommended) | `python website_workflow/tools/blog_compare.py <source> <run>/preview/<slug>/index.html` | operator | the "not found" passages |
| 4 Review | open the preview; read the validation report | **owner** | — |
| 5 Approve | `npm run blog -- approve <run> --by "<owner>" [--accept-warnings]` | operator, on the owner's word | `<run>/approvals/` |
| 6 Publish | `npm run blog -- publish <run> --site <site> --origin https://…` | operator | the transaction id it prints |
| 7 Verify | `git status` in the site; build the site; Phase 5 checks (below) | operator | build log, browser report |
| 8 Release | the site's normal release (website_flow.md Phase 6) | operator | — |
| 9 Record | decisions_log.md: run id, approver, digest, transaction id, accepted warnings | operator | — |

## Phase 5 checks for a new post

```
node tests/browser/blog-browser-check.cjs <served post URL> <served /blog URL> \
     --engines chromium,webkit,firefox --widths 320,768,1280 --out <run>/reports/browser.json [--axe <axe.min.js>]
```
Run it against the site served after a production build. It reports, per
engine and width: headings, landmarks, alt text, video controls, captions and
playback, accessible names, tables, measured text contrast, horizontal
overflow, the keyboard walk (focus visible, order, bypass) and runtime errors.
It prints every engine it could NOT run. Then do the manual checks in 14
(Safari/WebKit plan) and a screen-reader pass.

## Logs

| Log | Where | Contents |
|---|---|---|
| Stage history | `npm run blog -- history <run>` (`<run>/run-record.json`) | every preview, approval, publish, failure, recovery, rollback, lock takeover — time, digest, transaction |
| Transaction journal | `<run>/publish-tx/<id>/journal.json` | each file created/replaced/deleted, its hash |
| Site publish history | `<site>/.blog-publish-history.json` | committed publishes and files touched (site-relative; run NAMES only) |
| Ingest manifest | `<run>/manifest.json` | inputs, limits used, every issue with its action |

What the logs do NOT contain: document text beyond the manifest itself,
environment variables, secrets, absolute paths of source packages (the manifest
uses package-relative paths), or the approver's name in any file inside the
site. The approver's name is in the run directory only.

Error messages name files and routes, never file contents.

## Limits for production packages

Defaults suit ordinary blogs. Lower them for untrusted sources; raise them only
for trusted, large packages, and never beyond the fixed ceilings
(`--show-limits`).

```
python website_workflow/tools/blog_ingest.py <package> --out <run> \
  --max-file-mb 200 --max-files 500 --max-depth 8 --tool-timeout 120 --timeout 600 --memory-mb 2048
```

## Things operators must not do

- Edit a manifest, an asset in a run, or a published file by hand.
- Run `approve` without the owner's explicit word, or `rollback --force` /
  `unlock --force` without understanding why the safe path refused.
- Delete a run directory whose post may still need rolling back.
- Publish into a site directory that another process is changing.
